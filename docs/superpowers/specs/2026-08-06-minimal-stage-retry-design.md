# 最小失败阶段续跑设计

## 目标

所有人工或自动重试优先复用同一任务工作区中的有效输入、产物、校验记录和上传账本，只从最小失败阶段继续。只有输入已变、工作区或产物不可恢复时，才允许完整重跑。

## 范围

适用于视频、单条图文和批量图文。批量任务以视频键或图文组为最小修复单元。

## 当前根因

工作器已能为 Codex 直出视频恢复已保存的 `result.json` 和产物，但 `RENDER_EVIDENCE` 会禁止复用该结果，直接重新调用下游 Skill。图文任务也没有同等的“已验证结果优先”路径。因此轻微校验问题可能触发不必要的内容再生成。

## 方案比较

1. 仅扩展直出视频的续跑规则：改动最小，但单条图文和批量图文仍会重做。未采用。
2. 统一以工作区阶段、结果文件和产物校验决定续跑：三类任务共用规则，按单元修复。采用。
3. 为每类任务分别维护独立恢复流程：可高度定制，但重复代码和维护成本高。未采用。

## 续跑决策

1. 输入指纹或 Skill 版本不匹配、工作区缺失、已有产物哈希/结构无法修复：完整重跑。
2. 上传、回调、心跳等传输问题：复用结果，只重试上传和完成回调。
3. 结果格式、清单、校验记录缺失：复用已有产物，只补结果文件、缺失校验或证据记录。
4. 成片证据校验失败：先检查现有成片；无视觉缺陷时补做检查和证据，不重新渲染；只有明确记录了视觉缺陷时，才重做受影响视频的剪辑/渲染阶段。
5. 批量视频或批量图文中仅一个单元不合格：保留其他已通过单元，仅重做该视频键或图文组。
6. 轻微规则问题：返回员工端提醒，记录 `qualityWarnings`，不令任务失败或退回。

## 实现边界

- `WorkspaceState` 记录每个可恢复单元的阶段及其有效性；已有上传账本继续用于跳过重复上传。
- 恢复判断必须先验证 `result.json`、输出文件和任务契约，再进入内容生成分支。
- 不把无法证明有效的产物标记为成功；不伪造校验或渲染记录。
- 执行时间线明确记录 `RESUME_RESULT`、`RESUME_EVIDENCE_REPAIRED`、`RESUME_UNIT_REPAIRED` 或 `FULL_RERUN_REQUIRED`。

## 验收标准

- 视频证据记录缺失时，使用原 MP4 补校验并完成任务，测试证明不调用内容生成。
- 单条图文已有合格页面、仅缺结果元数据时，不重新生成页面。
- 批量图文或批量视频仅有一个失败单元时，其他单元的文件和上传账本保持不变。
- 输入变化、工作区丢失或损坏产物时，系统明确记录完整重跑原因。
- 轻微校验问题以警告完成并回传员工端。

## 已回传成品的异常处理

当任务已上传至少一个可审核成品时，后续校验、上传完成回调或对接写入出现异常，不将任务标记为失败或重新生成成品。任务进入待审核，员工端同时收到成品和问题说明，并由员工决定是否发起重试。仅在没有可审核成品时，保留失败和自动续跑流程。
