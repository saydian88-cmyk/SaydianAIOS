# AI 校验分级与员工提醒设计

## 目标

降低不影响交付的技术与质量提示造成的任务失败率，同时继续阻断无法交付、错误产品或存在合规风险的结果。

## 分级

### 硬阻断

以下情况保持失败或进入恢复流程，不能向员工交付：

- 不存在可读取的最终成片，或视频损坏。
- 不满足交付尺寸、时长、主成片类型等结果合同。
- 产品型号冲突、错误素材混入，或强制素材/来源约束不满足。
- 健康宣传合规、权限、上传、回传、存储或网络传输失败。
- 官方校验器明确报告产物不可用，而非证据字段或建议性质量问题。

### 提醒，不阻断

以下问题在有真实可交付成片时写入质量提醒并回传员工端，不消耗重试次数：

- 构图复核记录、三帧采样或 `reviewed_from_render` 等证据字段缺失。
- 字幕对比度、时间线密度、转场均匀性、包装细节等优化建议。
- 非合规、非交付合同的校验器警告。

## 执行链路

1. 执行器运行官方校验器，保留原始输出。
2. 校验结果经统一分类器转为 `BLOCKING` 或 `WARNING`。
3. `BLOCKING` 保持当前恢复/失败机制；`WARNING` 追加到任务质量提醒并继续上传与完成回调。
4. API 将提醒保存到任务结果和执行日志，员工端在任务详情与时间线显示“质量提醒”，不改变任务完成状态。

## 约束

- 不伪造官方校验证据，也不把未生成或不可读取的成片标记为完成。
- 不降低产品型号、合规、文件完整性、结果合同、上传和回传的阻断标准。
- 提醒必须包含来源校验器、原始信息摘要和建议动作，便于员工判断是否需要退回修改。

## 验收

- 仅含构图证据缺失的真实成片可完成，并在员工端看到提醒。
- 缺少 VIDEO_MASTER、文件损坏或产品型号冲突仍不能完成。
- 警告不会增加 `retryCount`，也不会触发失败通知。
- 原始官方校验输出仍可在执行日志中追溯。
